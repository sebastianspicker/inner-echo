## System model (how features work together)

`inner-echo` is a client-only app that composes condition-driven metaphoric effects over local media streams:

1. **UI orchestration (`src/ui/`)**
   - `CameraView` coordinates camera/audio lifecycle, mode/state controls, safety toggles, evidence navigation, and debug surfaces.
2. **Condition/profile layer (`src/conditions/`)**
   - Catalog + profiles define `video_stack`, optional `audio_stack`, safety clamps, and control metadata.
3. **Composer layer (`src/composer/`)**
   - Preset/multimorbid/symptom-first composition transforms user intent into normalized profile behavior.
4. **Runtime engine (`src/engine/`)**
   - Camera (`getUserMedia(video)`), overlay render loop (WebGL primary / Canvas2D fallback), audio engine, analyser metrics, and reactive coupling.
5. **Evidence plane (`src/evidence/`, `docs/references/`)**
   - In-app viewer loads repo-hosted markdown evidence and sanitizes output HTML before render.

This separation is coherent and avoids circular control flow: UI triggers engine APIs, engine consumes composed profiles, and evidence remains a read-only documentation plane.

### P2 (medium): issues found and remediated

1. **Eager loading of evidence viewer increased initial bundle footprint**
   - **Impact:** `CameraView` imported `EvidenceDrawer` eagerly, which pulled markdown/rendering dependencies into the main path.
   - **Remediation:** switched `EvidenceDrawer` to `React.lazy` + `Suspense`, isolating the evidence UI and markdown stack behind on-demand loading.
   - **Outcome:** production main JS bundle reduced from ~1004.48 kB to ~920.64 kB in this environment, with a dedicated `EvidenceDrawer` chunk emitted.

2. **Debug diagnostics panel included in eager app path**
   - **Impact:** debug-only panel code was imported at app startup even though it is only used in dev mode and only when the toggle is enabled.
   - **Remediation:** moved `DebugPanel` to lazy import, gated by existing dev + toggle checks.
   - **Outcome:** avoids eager debug payload in the default runtime path and keeps diagnostics fully available on demand.

3. **No user-visible loading state for lazy UI chunks**
   - **Impact:** lazy component boundaries previously used `fallback={null}`, creating a blank transition during chunk load.
   - **Remediation:** added a lightweight status fallback (`role="status"`, polite live region).
   - **Outcome:** improved perceived responsiveness and accessibility during async component load.
